# 2단계 화면 설계 (진사, 2026-11-05)

묶음 F. 진오(묶음 G)가 아래 HTML을 **클래스·id 그대로** 옮긴다. 스타일은 `client/css/style.css` 끝 `/* ---- 2단계 ---- */` 아래에 이미 들어 있다(원본·1단계 규칙 줄은 한 줄도 고치지 않음 — 위쪽 185줄이 시작 때와 같은 것을 diff로 확인).
모든 요소가 한 번에 보이는 확인용 파일: `docs/design/2단계_프로토타입.html` (`?s=start|join|group|overwrite|leave|toast|offline`). 진오는 이 파일의 마크업을 복사해도 된다.
기준: 본문 18px 이상(`1.125rem`), 누르는 곳 높이 48px 이상, 문구는 쉬운 우리말.

> **확인 상태**: 프로토타입을 Chrome으로 390×844·860×700·1280×800 세 크기, 7가지 상태(시작·참여·그룹 설정·덮어쓰기·나가기·알림·끊김 띠)로 캡처해 눈으로 확인했다 → `docs/design/2단계_캡처/F-*.png`(21장). 가로 넘침 없음. 아래 "폰 배치" 그림과 같은 모양이다.

## 0. 큰 그림

| 화면 | 어디에 | 어떻게 열림 |
|---|---|---|
| 시작 화면 `#startScreen` | `<body>` 안 `<main>` 앞 또는 뒤(고정 배치라 순서 무관), 화면 전체를 덮음 | 저장된 토큰이 없고 "혼자 쓰기"도 고르지 않았을 때, 또는 `?join=CODE` 주소, 또는 혼자 쓰기 중 "친구와 함께 쓰기" 누를 때 |
| 그룹 설정 창 `#groupDialog` | `<body>` 끝 | 패널의 `#groupBtn` (그룹 모드일 때) |
| 나가기 확인 `#leaveDialog` | `<body>` 끝 | 그룹 설정 창의 `#leaveBtn` |
| 덮어쓰기 확인창 `#overwriteDialog` | `<body>` 끝 | 확정이 409일 때, 또는 대기열 항목이 409일 때 |
| 남의 확정 알림 `#peerToast` | `<body>` 안(고정 배치) | 다른 사람의 `history:confirmed` 이벤트 |
| 연결 끊김 띠 `#connBar` | `<body>`의 **첫 자식** | `onConnection(false)` |

- `<body>`는 2열 격자라 **새 요소를 `<main>`·`<aside>` 사이에 격자 칸으로 넣지 않는다.** 위 요소는 모두 `position:fixed` 또는 `<dialog>`라 격자에 영향이 없다. `#connBar`·`#peerToast`·`#startScreen`은 `<body>` 직계 자식으로.
- 새 창은 모두 1단계처럼 `<dialog>`(+`showModal()`), 바깥 눌러도 닫지 않음. `#startScreen`만 `<section>`(창이 아니라 화면).
- `hidden` 속성으로 보이고 숨긴다(CSS가 `[hidden]{display:none}`을 챙김). 토글은 `el.hidden = true/false`.

## 1. 시작 화면 (2-6)

```html
<section id="startScreen" aria-labelledby="startTitle" hidden>
  <div class="start-inner">
    <h1 id="startTitle">한잔메뉴룰렛</h1>
    <p class="start-lead">오늘 뭐 먹을지, 같이 정해 봐요.</p>

    <div class="mode-row" role="group" aria-label="시작 방법">

      <button type="button" id="modeJoin" class="mode-btn" aria-pressed="false">코드로 참여</button>
```

동작 메모
- **모드 전환**: `#modeCreate`/`#modeJoin` 중 눌린 쪽만 `aria-pressed="true"`, 해당 폼만 보이고 다른 폼은 `hidden`. 전환해도 입력한 글은 지우지 않는다.
- **`?join=CODE`**: `modeJoin` 선택, `#joinCode`에 코드(대문자) 채움, 미리 보기 불러온 뒤 **포커스는 `#joinNick`**.
- **코드 입력**: 입력할 때 대문자로 바꾸고 허용 글자(`ABCDEFGHJKMNPQRSTUVWXYZ23456789`) 밖은 지움. 모양은 큰 글씨 한 칸(칸 6개로 쪼개지 않음 — 붙여넣기·음성 입력이 쉬움).
- **미리 보기**: 코드가 6글자가 되는 **순간 한 번만** `GET /api/invites/:code`(시도 제한이 10분에 10번이라 글자마다 부르면 안 됨). 성공 → `#joinPreview` 보임, `#joinGroupName`=그룹 이름, `#joinGroupCount`=`지금 {n}명이 함께 있어요`. 코드를 고치면 다시 `hidden`. 실패 → `#joinMsg`.
- **오류 문구**(`#createMsg`/`#joinMsg`, `role="alert"`, 입력은 유지): 이름/닉네임 비었을 때 "그룹 이름을 써 주세요." / "내 이름을 써 주세요." · 코드 없음 "초대 코드를 찾을 수 없어요. 다시 확인해 주세요." · 429 "너무 여러 번 시도했어요. {n}분 뒤에 다시 해 주세요." · 서버 연결 실패 "연결이 안 돼요. 잠시 뒤에 다시 해 주세요." · 그 밖 서버 `message` 그대로.
- **버튼 눌린 동안**: 보내는 중에는 제출 버튼 `disabled` + 글자 "잠시만요…", 끝나면 되돌림(두 번 눌림 방지).
- **`#importRow`**: 이 폰(혼자 쓰기 저장소)에 가져갈 것이 있을 때만 보임(없으면 `hidden`). `#importSummary` 숫자는 실제 값. 체크 해제 시 `importBoards` 없이 만든다.
- **혼자 쓰기**: `#soloBtn` → 시작 화면 닫고 1단계 그대로. 이 선택은 기기에 기억(키는 진오 결정; `hanjan.v1.device`)해 다음부터 시작 화면을 건너뛴다. 혼자 쓰기 중에는 `#groupBtn`이 "친구와 함께 쓰기"로 바뀌고 누르면 시작 화면을 다시 열며 `#startBackBtn`을 보여 준다.
- **시작 화면이 보이는 동안**: 뒤의 `<main>`·`<aside>`에 `inert` 를 붙이고(키보드·스페이스바가 룰렛으로 가지 않게), 닫을 때 뗀다. 열면 첫 포커스는 `#createGroupName`(만들기) 또는 코드 칸(`?join`이면 닉네임 칸).
- 입력 칸 글씨 18px·높이 48px 이상은 1단계 `.field input`을 그대로 쓴다. 코드 칸은 더 크게(높이 56px, 글씨 1.6rem).
- 어두운 바탕이므로 종이색 창 안 전용 `.btn-main`/`.btn-sub`를 쓰지 않고 `.btn-stamp`(빨강, 주 버튼)/`.btn-ghost`(테두리)를 쓴다.

## 2. 그룹 설정 창 (2-6)

```html
<dialog id="groupDialog" class="dlg" aria-labelledby="groupDialogTitle">
  <div class="dlg-head">
    <h2 id="groupDialogTitle">우리 팀 점심</h2>   <!-- 그룹 이름 -->
    <button type="button" id="groupCloseBtn" class="btn btn-sub">닫기</button>
  </div>
  <div class="dlg-body">
    <h3 style="margin-top:0">친구 부르기</h3>
    <div class="invite-code" id="inviteCode" role="text" aria-label="초대 코드">K7M2QX</div>
    <div class="invite-btns">
      <button type="button" id="copyLinkBtn" class="btn btn-main">초대 링크 복사</button>
      <button type="button" id="copyCodeBtn" class="btn btn-sub">코드만 복사</button>
    </div>
    <div id="copyMsg" role="status"></div>
    <div class="field"><label for="inviteLink">초대 링크</label>
      <input type="text" id="inviteLink" readonly></div>

    <h3 id="memberTitle">함께하는 사람 <span id="memberCount">3명</span></h3>

      <li class="member-row">
        <span class="member-name">민수</span>
        <span class="member-tag">만든 사람</span>   <!-- 만든 사람만 -->
        <span class="member-tag me">나</span>        <!-- 내 줄만 -->
      </li>
      <li class="member-row"><span class="member-name">영희</span></li>
    </ul>

    <h3>그룹 나가기</h3>
    <button type="button" id="leaveBtn" class="btn btn-danger btn-block">그룹에서 나가기</button>
  </div>
</dialog>

<dialog id="leaveDialog" class="dlg" role="alertdialog" aria-labelledby="leaveMsgTitle" aria-describedby="leaveSub">
  <div class="dlg-body">
    <p class="dlg-msg" id="leaveMsgTitle">이 그룹에서 나갈까요?</p>
    <p class="dlg-sub" id="leaveSub">나가면 이 폰에서는 그룹을 볼 수 없어요. 다시 들어오려면 초대 코드가 필요해요.</p>
    <div id="leaveMsg" role="alert"></div>
    <div class="dlg-actions">
      <button type="button" id="leaveNoBtn" class="btn btn-sub" autofocus>그대로 있기</button>
      <button type="button" id="leaveYesBtn" class="btn btn-danger">나가기</button>
    </div>
  </div>
</dialog>
```

동작 메모
- **복사**: `#copyLinkBtn` → `navigator.clipboard.writeText(location.origin + "/?join=" + code)`. 성공 `#copyMsg`="링크를 복사했어요", `#copyCodeBtn`은 "코드를 복사했어요". 복사가 안 되는 환경(HTTP·권한)이면 `#copyMsg`="복사가 안 돼요. 아래 링크를 길게 눌러 복사해 주세요." 하고 `#inviteLink`를 선택(`select()`). `#inviteLink`에는 항상 링크를 채워 둔다(읽기 전용).
- `#copyMsg`는 3초 뒤 비운다. 초록(`#1d6b3a`) + 굵은 글씨(색에만 기대지 않음). 복사 실패 문구도 같은 자리, 같은 굵기(색은 같아도 뜻이 글로 전달됨).
- **멤버 목록**: 나간 멤버는 넣지 않는다. 순서는 들어온 순. `#memberCount`는 `{n}명`. 이름이 길면 줄바꿈(`overflow-wrap:anywhere`).
- **나가기**: `#leaveBtn` → `#leaveDialog` 열기(그룹 설정 창은 그 아래에 열려 있어도 됨). "나가기" 성공 → 두 창 닫고 토큰 지운 뒤 시작 화면. 오류(예: 만든 사람인데 다른 멤버가 남음)는 서버 `message`를 `#leaveMsg`에 그대로("다른 멤버가 있으면 만든 사람은 나갈 수 없어요."), 창은 닫지 않는다. 첫 포커스는 **"그대로 있기"**(`autofocus`) — 실수로 Enter를 눌러도 나가지 않게.
- 오프라인에서 `#leaveBtn`은 `disabled`로 두지 말고 눌러서 `#leaveMsg`에 "연결되면 바꿀 수 있어요." (store가 주는 `OFFLINE` 메시지).

### 2-b. 그룹 화면으로 들어가는 버튼

메뉴 패널(`<aside>`) 맨 아래, `#boardSettingsBtn` **바로 아래 별도 줄**.

```html
  <button type="button" id="boardSettingsBtn">메뉴판 설정</button>
  <button type="button" id="groupBtn"><span class="gb-label">그룹 설정</span><span class="gb-name" id="groupBtnName">우리 팀 점심</span></button>
</aside>
```

- 그룹 모드: `.gb-label`="그룹 설정", `#groupBtnName`=그룹 이름(길면 …로 잘림). 누르면 `#groupDialog`.
- 혼자 쓰기 모드: `.gb-label`="친구와 함께 쓰기", `#groupBtnName`은 비움(`:empty`면 CSS가 숨김). 누르면 시작 화면.
- 높이 56px 이상, 글씨 1.125rem 굵게, 테두리 보조 버튼 모양. 회전 중에는 `aside` 전체가 잠기므로(원본 `body.busy aside`) 따로 처리할 것 없음.
- 폭 860px 이하: 패널이 룰렛 아래로 내려가도 같은 위치(패널 맨 아래), 가로 가득.

## 3. 덮어쓰기 확인창 (2-7)

```html
<dialog id="overwriteDialog" class="dlg" role="alertdialog" aria-labelledby="overwriteMsg" aria-describedby="overwriteSub">
  <div class="dlg-body">
    <p class="dlg-msg" id="overwriteMsg"><b id="overwriteWho">민수</b>님이 <b id="overwriteMenu">김치찌개</b>로 확정했어요. 바꿀까요?</p>
    <p class="dlg-sub" id="overwriteSub">내가 고른 메뉴: <b id="overwriteMine">제육볶음</b></p>
    <div class="dlg-actions">
      <button type="button" id="overwriteNoBtn" class="btn btn-sub" autofocus>그대로 두기</button>
      <button type="button" id="overwriteYesBtn" class="btn btn-main">바꾸기</button>
    </div>
  </div>
</dialog>
```

- 문구는 **정확히** `{닉네임}님이 {메뉴}로 확정했어요. 바꿀까요?`. 닉네임·메뉴는 `textContent`로 넣는다(`innerHTML` 금지). 닉네임이 비면 "누군가"로.
- `#overwriteSub`("내가 고른 메뉴")는 보낼 메뉴 이름을 알 때 보여 준다. 모르면 `hidden`.
- **버튼 순서**: "그대로 두기"(왼쪽/위)·"바꾸기"(오른쪽/아래). 첫 포커스와 Esc는 **"그대로 두기"** — 실수로 남의 확정을 덮지 않게. Esc는 `cancel` 이벤트이므로 "그대로 두기"와 같은 처리.
- 폭 860px 초과: 가운데 뜨는 창(폭 30rem), 버튼 가로 나란히. 폭 860px 이하: 아래에서 올라오는 시트, **버튼은 위아래 한 줄씩 가로 가득**(그대로 두기가 위).
- 대기열에서 온 409가 여러 개면 한 번에 하나씩, 앞 창이 닫힌 뒤 다음 것. 회전 중이면 회전이 끝난 뒤 연다(2-8).

## 4. 남의 확정 알림 (2-7)

```html
<div id="peerToast" role="status" hidden>
  <span id="peerToastText">민수님이 김치찌개로 확정했어요</span>
  <button type="button" id="peerToastClose">확인</button>
</div>
```

- 문구 `{닉네임}님이 {메뉴}로 확정했어요`(`textContent`로). 화면 **위쪽 가운데**에 뜬다(원본 `#toast`는 아래라 겹치지 않음).
- **8초 뒤 자동으로 사라짐**(어르신이 읽을 시간) 또는 "확인" 누르면 닫힘. 새 알림이 오면 글만 바꾸고 시간을 다시 잼. `role="status"`라 읽어 준다(포커스를 빼앗지 않음).
- 내가 한 확정에는 띄우지 않는다. 결과 카드는 확정한 본인에게만(지시서) — 남의 확정은 이 알림과 상단 배지(`#today`)만.
- 창(`<dialog>`)이 열려 있는 동안은 창 뒤에 가려지므로, 열린 창이 있으면 닫힌 뒤 보여 준다. 회전 중이면 회전이 끝난 뒤(2-8).
- 연결 끊김 띠가 떠 있으면(`body.is-offline`) 띠 아래로 내려간다(CSS가 처리).
- 움직임 줄이기 설정이면 위에서 내려오는 움직임 없이 바로 나타난다.

## 5. 연결 끊김 띠 (2-7)

```html
<body>
<div id="connBar" role="status" hidden>
  <span class="conn-dot" aria-hidden="true"></span>
  <span class="conn-main">연결이 끊겼어요. 다시 연결하는 중…</span>
  <span class="conn-sub">돌리기·확정은 그대로 할 수 있어요</span>
</div>
```

- **끊김**: `#connBar.hidden = false` **그리고** `document.body.classList.add("is-offline")`. **연결됨**: 둘 다 되돌림. (`is-offline`이 본문·패널 위 여백을 늘려서 띠가 메뉴판 줄을 가리지 않게 한다. 띠 높이가 달라지므로 두 글을 바꾸지 말 것.)
- 화면 맨 위에 붙은 얇은 띠(살구색 바탕 + 남색 글씨, 점이 천천히 깜빡임). 폭 860px 초과는 한 줄(높이 2.5rem), 폰은 두 줄(첫 줄 "연결이 끊겼어요…", 둘째 줄 안심 문구, 높이 3.7rem).
- "돌리기·확정은 그대로 할 수 있어요" 줄이 **오프라인에서도 쓸모가 있다는 것**을 알려 준다. 메뉴·메뉴판 편집은 막히며, 그때 문구는 store의 `연결되면 바꿀 수 있어요.`를 각 화면의 기존 오류 자리(`#addMsg`, `#boardMsg`)에 보여 준다.
- 다시 연결되면 띠를 바로 치운다(별도 "연결됐어요" 알림은 두지 않는다). 대기열 전송 중 409는 3장 확인창.
- 띠는 `role="status"`라 끊김이 읽힌다. 움직임 줄이기 설정이면 점 깜빡임 없음.
- 처음 접속 직후(아직 연결 시도 중)에는 띠를 띄우지 않는다 — `onConnection(false)`가 실제로 한 번 연결된 뒤 끊겼거나, 첫 연결이 3초 넘게 안 될 때만.

## 7. 키보드·접근성·움직임

- 모든 새 요소는 `button`/`input`/`label`/`dialog`라 Tab·Enter·Space가 그대로. 포커스 표시: 어두운 바탕은 종이색 테두리, 종이색 창 안은 남색, 시작 화면 입력 칸은 살구색 굵은 테두리.
- 모드 버튼은 `aria-pressed`, 오류·복사 결과·알림·띠는 `role="alert"`/`role="status"`로 읽힘. 오류는 색 + 굵은 글씨 + 글로 전달.
- 확인창 둘은 `role="alertdialog"`, 안전한 쪽(그대로 두기/그대로 있기)이 첫 포커스.
- `<dialog>`가 열려 있으면 스페이스바로 안 돌린다(1단계 규칙 `dialog[open]` 그대로). 시작 화면이 열려 있을 때는 `inert`로 막는다.
- **움직임 줄이기**(`prefers-reduced-motion: reduce`): 알림이 내려오는 움직임·끊김 점 깜빡임·새 버튼 전환 모두 없음(기본 설정에서만 켜짐). 1단계 `.dlg[open]` 올라오는 애니메이션도 같은 규칙으로 꺼짐.

## 8. 진오에게 따로 부탁

- 새 id/class가 더 필요하면 진사에게 알려 주세요(진오가 `style.css`를 고치지 않는다).
- 문구 변경은 이 문서 문구 그대로. 특히 확인창 `{닉네임}님이 {메뉴}로 확정했어요. 바꿀까요?`·버튼 "바꾸기"/"그대로 두기", 알림 `{닉네임}님이 {메뉴}로 확정했어요`, 띠 "연결이 끊겼어요. 다시 연결하는 중…".
- `?join=` 코드 채움·미리 보기 호출은 **글자마다 부르지 않기**(시도 제한).
- 서버가 준 문자열(닉네임·그룹 이름·메뉴)은 항상 `textContent`로.
