# 1단계 화면 설계 (진사, 2026-11-05)

묶음 B. 진오(묶음 C·D)가 아래 HTML을 **클래스·id 그대로** 옮긴다. 스타일은 `client/css/style.css` 끝 `/* ---- 1단계 ---- */` 아래에 이미 들어 있다(원본 규칙 줄은 한 줄도 고치지 않음 — 위쪽이 시작 파일과 같은 것을 diff로 확인).
기준: 본문 18px 이상(`1.125rem`), 누르는 곳 높이 48px 이상, 문구는 쉬운 우리말.

## 0. 큰 그림

| 화면 | 어디에 | 어떻게 열림 |
|---|---|---|
| 메뉴판 줄 `#boardBar` | `<main>` 맨 위(`#today` 앞) | 항상 보임 |
| 메뉴판 관리 창 `#boardDialog` | `<body>` 끝 | "+" 누르기(새로 만들기), 탭 길게 누르기 0.5초 / `contextmenu`(편집) |
| 기록 창 `#historyDialog` | `<body>` 끝 | "기록" 버튼 |
| 삭제 확인 | 새 창 없음. 원본 "되돌리기"처럼 `confirm()` | 관리 창의 "삭제" |

창은 모두 `<dialog>`(+`showModal()`). 얻는 것: 포커스가 창 안에 갇힘, Esc로 닫힘, 닫으면 열었던 버튼으로 포커스 복귀. 바깥(어두운 곳) 눌러도 **닫지 않는다**(입력하다 날리는 일 방지).
"대화창이 열려 있으면 스페이스바로 안 돌림" 판정: `document.querySelector("dialog[open]")` 가 있으면 무시.

## 1. 메뉴판 줄 (1-2)

```html
<main>
  <div id="boardBar">
    <div id="boardTabs" aria-label="메뉴판">
      <!-- 메뉴판마다 하나. 현재 것만 aria-current="true" -->
      <button type="button" class="tab" data-board-id="b1" aria-current="true">점심</button>
      <button type="button" class="tab" data-board-id="b2">술 한잔</button>
    </div>
    <button type="button" id="addBoardBtn" aria-label="새 메뉴판 만들기">+</button>
    <button type="button" id="historyBtn">기록</button>
  </div>
  <div id="today"></div>
  ...
```

- 탭 글씨는 **메뉴판 이름 전체**(최대 12자). 칸이 넘치면 CSS가 `…`로 자른다(`max-width:11rem`). 잘린 탭은 `title` 속성에 전체 이름을 넣는다.
- 탭이 많으면 `#boardTabs`만 가로로 밀린다(`overflow-x:auto`, 손가락 밀기·가로 스크롤 모두). "+"와 "기록"은 밀리지 않고 항상 오른쪽에 보인다.
- **현재 탭 표시**: 색을 뒤집는다(종이색 바탕 + 남색 글씨). 색만으로 구분하지 않도록 `aria-current="true"`도 함께 둔다.
- 메뉴판을 바꾸거나 다시 그린 뒤 현재 탭이 가려졌으면 `tab.scrollIntoView({ inline:"center", block:"nearest" })`(움직임 줄이기 설정이면 CSS가 부드러운 이동을 끔).
- 탭 눌러 바꾸기 = `click`. 길게 누르기: `pointerdown` 후 500ms 안에 `pointerup`/`pointermove`(10px 넘게)/`pointercancel` 이 없으면 편집 창 열기, 이때 뒤따르는 `click`은 무시. `contextmenu` 이벤트는 `preventDefault()` 후 같은 편집 창 열기.
- 회전 중(`body.busy`)에는 줄 전체가 반투명 + `pointer-events:none`(CSS 처리됨). 키보드로 탭 이동은 `button`이라 Tab/Enter/Space 그대로(회전 중엔 JS에서 `disabled` 대신 CSS로 막혀도 되지만, 키보드까지 막으려면 `#boardBar`에 `inert` 를 `busy` 때 붙이고 뗀다 — 권장).
- 상단 배지 `#today`, 결과 카드 `#card .lead`는 기존 id 그대로(1-4).

### 1-b. 메뉴판 설정 버튼 (사용자 승인, 묶음 D에 포함)

탭 길게 누르기·`contextmenu`는 그대로 두고, 눈에 보이는 길을 하나 더 둔다. 메뉴 패널(`<aside>`) 맨 아래, 원본 `#foot` 줄 **바로 아래 별도 줄**에 가로 가득 놓는다. `#foot`(소리·처음 메뉴로 되돌리기, 19rem 패널에서 이미 빠듯함) 안에는 넣지 않는다.

```html
  <div id="foot">
    <button id="snd" type="button">소리 꺼짐</button>
    <button id="resetBtn" type="button">처음 메뉴로 되돌리기</button>
  </div>
  <button type="button" id="boardSettingsBtn">메뉴판 설정</button>
</aside>
```

- 누르면 **지금 보고 있는 메뉴판**의 고치기 창(2장 `#boardDialog`, "메뉴판 고치기")을 연다. 길게 누르기와 같은 `openEdit(현재 메뉴판 id)`. 창을 닫으면 포커스는 이 버튼으로 돌아온다(열었던 버튼으로 복귀 — 탭이 아니라 이 버튼에서 열었으면 이 버튼).
- 회전 중(`body.busy`)은 `body.busy aside { pointer-events:none; opacity:.5 }`(원본 규칙)로 이미 잠긴다. 키보드까지 막으려면 다른 패널 버튼처럼 처리하되, 원본 버튼들이 따로 `disabled` 처리가 없다면 이 버튼도 같게 둔다(마우스·터치만 막혀도 됨 — 열린 창 안에서 `spin`은 `dialog[open]` 검사로 이미 막힘).
- 글씨 `1.125rem`·굵게, 높이 48px 이상, 테두리만 있는 보조 버튼 모양(주 버튼 아님). 스타일은 `style.css` 끝에 이미 추가함(`#boardSettingsBtn`).
- 폭 860px 이하: 패널이 룰렛 아래로 내려가도 같은 위치(패널 맨 아래), 가로 가득.
- 메뉴판이 하나도 없을 수는 없으므로(최소 1개) 숨기거나 비활성으로 만들 일은 없다.

## 2. 메뉴판 관리 창 (1-3)

```html
<dialog id="boardDialog" class="dlg" aria-labelledby="boardDialogTitle">
  <form id="boardForm" class="dlg-body" autocomplete="off" novalidate>
    <h2 id="boardDialogTitle">새 메뉴판</h2>   <!-- 편집: "메뉴판 고치기" -->

    <div class="field">
      <label for="boardName">메뉴판 이름</label>
      <input type="text" id="boardName" maxlength="12" aria-describedby="boardNameHint">
      <div class="field-hint" id="boardNameHint">12자까지 쓸 수 있어요.</div>
    </div>

    <div class="field">
      <label for="boardLead">결과에 보여 줄 말</label>
      <input type="text" id="boardLead" maxlength="20" aria-describedby="boardLeadHint">
      <div class="field-hint" id="boardLeadHint">돌린 뒤 메뉴 위에 나와요. 예: 오늘 점심은</div>
    </div>

    <!-- 만들 때만 보임. 편집 창에서는 hidden 속성을 붙인다 -->
    <fieldset id="templateField">
      <legend>처음에 넣을 메뉴</legend>
      <label class="choice"><input type="radio" name="template" value="lunch" checked>
        <span><b>점심</b><small>김치찌개, 제육볶음 등 8개</small></span></label>
      <label class="choice"><input type="radio" name="template" value="drinks">
        <span><b>술 한잔</b><small>고깃집, 치킨집 등 8곳</small></span></label>
      <label class="choice"><input type="radio" name="template" value="empty">
        <span><b>빈 메뉴판</b><small>메뉴 없이 시작해요</small></span></label>
    </fieldset>

    <label class="choice switch">
      <input type="checkbox" id="boardExclude" checked>
      <span><b>어제 먹은 메뉴는 빼기</b><small>끄면 어제 먹은 메뉴도 다시 나와요</small></span>
    </label>

    <div id="boardMsg" role="alert"></div>

    <div class="dlg-actions">
      <button type="button" id="boardDeleteBtn" class="btn btn-danger" hidden>이 메뉴판 지우기</button>
      <button type="button" id="boardCancelBtn" class="btn btn-sub">취소</button>
      <button type="submit" id="boardSaveBtn" class="btn btn-main">저장</button>
    </div>
  </form>
</dialog>
```

동작 메모
- **새로 만들기**: 제목 "새 메뉴판", 템플릿 묶음 보임(기본 "점심"), `boardDeleteBtn`은 `hidden`. 템플릿을 고르면 이름·문구 칸이 **비어 있을 때만** 템플릿 기본값(`templates.js`의 기본 이름·결과 문구)을 채운다(사용자가 쓴 글은 덮지 않음). 이름 칸이 비어 있어도 저장하면 템플릿 기본 이름을 쓴다.
- **고치기**: 제목 "메뉴판 고치기", 현재 값 채움, `templateField`에 `hidden`, 삭제 버튼 보임.
- 저장 오류는 `#boardMsg`에 store가 준 `message` 그대로("메뉴판은 10개까지 만들 수 있어요." 등). 오류가 나면 창을 닫지 않는다.
- **삭제**: `confirm("‘{이름}’ 메뉴판을 지울까요? 이 메뉴판의 기록도 함께 사라져요.")` → 확인하면 `deleteBoard`. 마지막 1개면 store의 "메뉴판은 1개 이상 있어야 해요."를 `#boardMsg`에 보여 준다(삭제 버튼을 아예 숨기지는 않음).
- 취소·Esc·저장 성공 시 닫고, 열었던 버튼(또는 해당 탭)으로 포커스를 돌려준다.
- 이름 칸은 열릴 때 자동으로 첫 포커스를 받는다(`<dialog>` 기본 동작). 폰에서는 키보드가 바로 올라온다 — 새로 만들기에서는 적절, 고치기에서 거슬리면 보고해 주세요.

## 3. 기록 창 (1-6, 묶음 D)

```html
<dialog id="historyDialog" class="dlg" aria-labelledby="historyTitle">
  <div class="dlg-head">
    <h2 id="historyTitle">기록</h2>
    <button type="button" id="historyCloseBtn" class="btn btn-sub">닫기</button>
  </div>
  <div class="dlg-body">
    <!-- 메뉴판 고르기: 현재 것만 aria-pressed="true" -->
    <div id="historyBoards" class="chips" aria-label="메뉴판 고르기">
      <button type="button" class="chip" data-board-id="b1" aria-pressed="true">점심</button>
      <button type="button" class="chip" data-board-id="b2" aria-pressed="false">술 한잔</button>
    </div>

    <h3 id="statsTitle">많이 나온 메뉴</h3>
    <div id="rangeBtns" class="seg" aria-label="기간">
      <button type="button" data-range="30" aria-pressed="true">30일</button>
      <button type="button" data-range="90" aria-pressed="false">90일</button>
      <button type="button" data-range="all" aria-pressed="false">전체</button>
    </div>
    <ul id="statsList" class="bars" aria-labelledby="statsTitle">
      <li class="bar-row">
        <span class="bar-name">김치찌개</span>
        <span class="bar-count">5번</span>
        <span class="bar-track"><span class="bar-fill" style="--pct:100%"></span></span>
      </li>
    </ul>
    <p id="statsEmpty" class="empty-msg" hidden>이 기간에는 확정한 메뉴가 없어요.</p>

    <h3 id="historyListTitle">날짜별 기록</h3>
    <ul id="historyList" class="h-list" aria-labelledby="historyListTitle">
      <li class="h-row">
        <time class="h-date" datetime="2026-11-05">11월 5일 (목)</time>
        <span class="h-menu">김치찌개</span>
        <span class="h-who">나</span>
      </li>
    </ul>
    <p id="historyEmpty" class="empty-msg" hidden>아직 기록이 없어요. 돌려서 확정하면 여기에 쌓여요.</p>
    <button type="button" id="historyMore" class="btn btn-sub" hidden>더 보기 (30일 더)</button>
  </div>
</dialog>
```

동작·문구 메모
- 막대 길이: `--pct` = `count / 맨 위 항목의 count × 100`(맨 위가 100%). 숫자는 항상 "N번"으로 같이 적는다(막대만으로 읽게 하지 않음). `--pct`는 `li.style.setProperty` 또는 `style` 속성 어느 쪽이든 된다.
- 날짜 표기: `M월 D일 (요일)`, **올해가 아니면** `YYYY년 M월 D일 (요일)`. 요일은 `new Date(dateStr + "T00:00:00Z")`를 UTC로 읽어 계산(시간대 영향 없음). 가장 최신이 위.
- "확정한 사람" 칸 `.h-who`: 닉네임이 비면 "나"(지시서 규칙).
- `#historyMore`는 `hasMore`일 때만 보인다(`hidden` 제거). 누르면 30일 더 붙이고, 누른 뒤 새로 생긴 첫 줄로 포커스를 옮기지는 않는다(스크롤 위치 유지). 기록이 더 없으면 다시 `hidden`.
- 기간 버튼은 막대 목록만 바꾼다(날짜 목록은 그대로). 다른 메뉴판을 고르면 두 목록 모두 새로 그리고 기간은 30일로 돌린다.
- 창을 열 때 선택된 메뉴판 = 지금 보고 있는 메뉴판. 메뉴판이 지워지면 첫 번째로.
- 기록 창이 열려 있는 동안 메뉴판이 다른 탭에서 바뀌면(subscribe) 목록만 다시 그린다.

## 4. 폭 860px 이하

- 메뉴판 줄은 `<main>` 맨 위에 그대로(룰렛 위). 탭만 가로로 밀림, "+"·"기록" 고정.
- 창(`.dlg`)은 **화면 아래에서 올라오는 시트**: 가로 가득, 위쪽 모서리만 둥글게, 최대 높이 92dvh에 안에서 스크롤. 기록 창 제목줄(닫기 버튼)은 스크롤해도 위에 붙어 있다.
- 관리 창 버튼: "이 메뉴판 지우기"가 맨 위 한 줄, 그 아래 취소·저장이 반반.
- 860px 초과에서는 가운데 뜨는 창(폭 34rem).

## 5. 키보드·접근성

- 모든 새 요소는 `button`/`input`/`label`이라 Tab·Enter·Space가 그대로 동작. 포커스 표시는 기존 `:focus-visible`(어두운 바탕은 종이색 테두리, 창 안은 남색 테두리).
- 라디오/체크 선택지(`.choice`)는 글자 칸 전체가 눌림(높이 56px 이상). 포커스는 칸 둘레에 굵은 테두리.
- 오류 문구 `#boardMsg`는 `role="alert"`라 읽어 준다. 색(진한 빨강) + 굵은 글씨로, 색에만 기대지 않는다.
- 창이 열린 동안 뒤 화면은 `showModal()`이 막아 준다(스페이스·Tab이 룰렛에 가지 않음).
- **움직임 줄이기**(`prefers-reduced-motion: reduce`): 새 요소의 전환·창 올라오는 애니메이션·탭 부드러운 이동 모두 없음(기본 설정에서만 켜짐). 0단계 점검 22와 같은 방식.

## 6. 진오에게 따로 부탁

- `<title>`은 `한잔메뉴룰렛`.
- 마크업 순서/위치는 위 그대로. `#boardBar`를 `<main>` 밖이나 `body` 격자(grid)의 새 칸으로 빼지 말 것 — `body`가 2열 격자라 칸이 늘면 룰렛·패널 배치가 깨진다.
- 새 id/class를 더 만들 일이 생기면 CSS가 필요하니 진사에게 알려 주세요(진오가 `style.css`를 고치지 않는다).

## 7. 진록에게 알림 (설계와 다른 점은 아님, 판단 요청)

1. **0단계 시험의 전체 화면 비교(`compare-shots.mjs`)는 1단계에서 원본과 달라진다.** 메뉴판 줄이 룰렛 위에 항상 보이니 룰렛이 그만큼 작게 그려지고 화면 픽셀이 다를 수밖에 없다. 캔버스 **내용** 비교(시험 C)는 영향 없음 — 비트맵은 900×900 고정. 1단계 회귀는 시험 C·D 23항목으로 하고 `compare-shots`는 "원본과 같음" 기준에서 뺄 것을 제안.
2. **(승인됨 → 1-b장에 반영)** 발견하기 어려운 길게 누르기: 어르신이 "탭 길게 누르기"로 편집을 찾기는 어렵다. 메뉴판 패널 아래 `#foot` 줄에 "메뉴판 설정" 버튼 하나를 더 두면 훨씬 쉽다(누르면 현재 메뉴판 편집 창). 설계(1-2)에는 없는 요소라 **추가 전에 승인 필요**. 승인되면 CSS 한 규칙만 더 한다.
3. 삭제 확인에 새 창을 만들지 않고 원본 "처음 메뉴로 되돌리기"와 같은 `confirm()`을 쓴다(시험도 쉬움). 큰 글씨 확인창이 필요하면 알려 주세요.
