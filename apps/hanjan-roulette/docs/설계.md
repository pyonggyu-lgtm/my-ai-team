## 2. 원본 코드를 모듈로 나누는 계획 (0단계 핵심)

### 2.1 원칙

1. **동작이 한 글자도 바뀌지 않는다.** 안내 문구, 확인창 문구, 숫자(50/42/34px, 5초, 5~7바퀴, ±35%, 0.35초, 140조각, 4초, 30건)를 그대로 옮긴다.
2. **순수 함수와 화면 코드를 가른다.** `pool.js`와 `wheel.js`의 계산 부분은 DOM·localStorage·`Math.random`에 직접 손대지 않게 만들어, Node에서 바로 시험하고 2단계 서버에서도 그대로 불러 쓴다.
3. **무작위 함수는 주입한다.** `rng = Math.random`을 기본값 인자로 받아, 시험에서는 고정된 값을 넣어 결과를 재현한다.
4. 0단계에서는 localStorage 키를 원본과 같은 `lunchRoulette.v1.`로 둔다(원본과 비교 시험을 하려고). 1단계에서 `hanjan.v1.`로 바꾼다.
5. `<script type="module">`은 `file://`로 열리지 않는다. 그래서 0단계부터 `node tools/serve.mjs`(설치할 것 없음, Node만 있으면 됨)로 `http://localhost:8080`에서 연다. Node가 없으면 `python3 -m http.server 8080 -d client`로 대신한다.

### 2.3 모듈별 공개 함수

**`pool.js`** — 순수 함수만. 브라우저와 서버가 함께 쓴다.
```js
export function yesterdayName(history, today)        // 오늘이 아닌 가장 최근 기록의 name, 없으면 null
export function todayConfirmed(history, today)       // 오늘 기록의 name, 없으면 null
export function computePool({ items, skippedNames, yesterday, excludeYesterday = true })
  // → { pool: string[], block?: true, single?: true, msg: string, resetSkipped?: true }
export function itemTag(item, { confirmed, skippedNames, yesterday })  // "오늘 확정" | "오늘 넘김" | "어제 먹음" | ""
```
- 원본 `computePool`은 넘김을 모두 써 버렸을 때 **스스로 `skipped`를 비우고 저장**한다(195줄). 이 부작용을 빼고 `resetSkipped: true`를 돌려준다. `app.js`가 이 값을 보고 넘김을 비워 저장한다. 계산 결과와 문구는 원본과 같다("모든 메뉴를 한 번씩 넘겨서 처음부터 다시 돌려요." + 이어지는 문구).
- `excludeYesterday`는 0단계에서 항상 `true`(원본과 같음). 1단계부터 메뉴판 설정을 넘긴다. `false`면 `yesterday`를 `null`로 보고 계산하고, 태그 "어제 먹음"도 붙이지 않는다.
- 2단계에서 어제 메뉴는 "배열의 마지막"이 아니라 "날짜가 오늘보다 앞선 기록 중 가장 늦은 날짜"로 정한다. 원본은 기록을 날짜순으로만 쌓으므로 두 방식의 결과가 같다(시험으로 확인).

**`wheel.js`**
```js
export const PALETTE, FONT, TAU, SPIN_SEC; export const mod, ease, segColor, shortName;
export function indexUnderPointer(theta, n)                 // 순수
export function planSpin(theta, n, rng = Math.random)       // 순수 → { k, delta }  (당첨 칸 먼저 정함, 원본 288–291줄)
export function drawWheel(ctx, names, theta, pointerKick)   // 캔버스 그리기
export function animateSpin({ ctx, names, from, delta, onTick }) // → Promise<finalTheta>, 원본 296–307줄의 프레임 루프
```
- `planSpin`이 정한 `k`와 애니메이션이 실제로 멈춘 칸이 같은지가 이 앱의 공정성이다. 시험으로 고정한다(3.1).
- 4단계 "회전 중계"에서는 `{ names, from, delta }`만 다른 기기에 보내면 같은 회전이 재생되도록 이 구조를 미리 잡아 둔다.

**`effects.js`**
```js
export function setSound(on); export function tick(); export function chime();
export function startConfetti(canvas); export function stopConfetti();
```
- `AudioContext`는 원본처럼 첫 소리 낼 때 만든다(클릭 뒤에만 시작).

**`app.js`** — 상태 보관, 저장, `render()`, 결과 카드, 메뉴 목록·추가·삭제·되돌리기·초기화, 소리 버튼, 돌리기 버튼·스페이스바, 글꼴 로드 후 다시 그리기. 원본 `spin()` 흐름은 여기서 그대로 이어 붙인다:
`computePool → (resetSkipped면 넘김 비움) → render → block이면 끝 → single이면 바로 결과 → wheelNames 고정 → planSpin → busy 켜기 → animateSpin(onTick: 포인터 튕김+tick) → busy 끄기 → showResult`

### 2.4 글꼴 분리

- 진사가 원본 HTML 안의 base64 두 덩어리(500·700)를 **명령줄로 꺼낸다**(파일을 사람이 읽지 않고 `grep -o`/`sed` + `base64 -d`로 바로 파일에 씀). 결과: `client/fonts/Pretendard-Medium.woff2`, `Pretendard-Bold.woff2`.
- 확인: 두 파일의 첫 4바이트가 `wOF2`, 크기 합이 원본 HTML 크기에서 원본_코드만.html 크기를 뺀 값의 약 3/4(base64 디코딩 비율).
- Pretendard는 SIL Open Font License라 파일로 나눠 배포해도 된다. 라이선스 문구를 `client/fonts/LICENSE.txt`로 함께 둔다(진삼이 원문 확인).

**완료 기준 "원본과 똑같이 동작하는 화면이 내 PC에서 열림"의 시험**

**같이 쓰는 규칙의 구현 방식**
- **서버가 유일한 기준**: 모든 쓰기는 REST API로 하고, 성공하면 서버가 그 그룹 방에 WebSocket 이벤트를 보낸다. WebSocket으로는 쓰지 않는다(4단계 회전 중계만 예외). 검증 경로가 하나라 오프라인 대기열도 단순해진다.
- **이벤트는 메뉴판 통째로**: 메뉴판 하나는 메뉴 16개 이하라 작다. 바뀐 부분만 보내지 않고 메뉴판 전체(메뉴·오늘 넘김·오늘 확정·어제 메뉴)와 `rev`(바뀔 때마다 1씩 오르는 번호)를 보낸다. 받은 쪽은 가진 것보다 `rev`가 크면 갈아 끼우기만 한다. 순서가 꼬이거나 두 번 받아도 안전하다.
- **다시 연결되면 전체 다시 받기**: 재연결 시 `GET /api/groups/:gid/state`로 다시 받는다. 끊긴 사이 놓친 이벤트를 따로 챙기지 않는다.
- **날짜**: 서버가 `today`를 정해 응답·이벤트에 넣는다. 한국 자정에 서버가 `day:changed`를 보내 모든 기기가 "어제"·넘김을 다시 계산한다.
- **동시 확정**: `history`의 `(board_id, date)` 유일 제약. `overwrite:false`로 보냈는데 이미 있으면 409와 함께 기존 기록(메뉴·확정한 사람)을 돌려준다 → 확인창 → 바꾸면 `overwrite:true`로 다시 보냄. 확정과 "그 메뉴판 오늘 넘김 비우기"는 한 트랜잭션.
- **넘김 공유**: "다시 돌리기"는 화면에서 먼저 넘김에 넣고(바로 다시 돌리기 위해) 서버에 보낸다. 모든 메뉴를 넘겨 `resetSkipped`가 나오면 `DELETE .../skipped`.
- **회전 중 보호**: `store-remote.js`가 이벤트를 받으면 상태를 갱신하되, `app.js`가 회전 중이면 `render()`를 미루고 회전이 끝날 때 한 번 그린다. 룰렛에 올라간 이름은 회전 시작 때 고정되므로(원본과 같음) 그사이 메뉴가 지워져도 당첨 결과는 그대로 확정할 수 있다.
- **오프라인**(1단계 수준 유지): 마지막 상태를 기기에 저장해 두어 연결 없이도 열고 돌릴 수 있다. 확정·넘김은 대기열(`hanjan.v1.outbox`)에 넣었다가 연결되면 순서대로 보낸다. 그사이 다른 사람이 확정했으면 409 → 덮어쓰기 확인창. 오프라인에서 **메뉴 추가·끄기·삭제와 메뉴판 편집은 막는다**(겹치는 수정 충돌을 피하려고, 결정 필요 2번).

**완료 기준 "폰 2대로 동시에 써서 결과·기록이 똑같이 보임"의 시험**

- **서버 통합 시험** (`node --test tests/server`, 실제 서버를 임의 포트·임시 DB 파일로 띄움, 시계는 시험용으로 바꿔 끼울 수 있게 `now()`를 주입):
  ① 토큰 없음 401, 다른 그룹 토큰 403 — 4장 모든 API에 대해 반복. ② 초대 코드 11번 틀리면 429. ③ 같은 메뉴판·같은 날 확정 2건을 동시에 보냄 → 정확히 하나 201, 하나 409(내용에 먼저 확정한 사람). ④ `overwrite:true`면 바뀌고 넘김이 비워짐. ⑤ 메뉴 17개째·중복 이름·21자·메뉴판 11개째 거부. ⑥ 한국 23:59:59와 00:00:00에 확정 → 서로 다른 날짜로 저장, "어제 메뉴" 계산 맞음. ⑦ DB에 토큰 원문이 없음(해시만). ⑧ 소켓: A가 메뉴를 끄면 B가 1초 안에 `board:updated` 수신, 다른 그룹 C는 받지 않음. ⑨ 나간 멤버의 토큰은 다시 401, 소켓도 끊김.
- **클라이언트 단위 시험**: 대기열(끊김 중 쌓기 → 재연결 시 순서대로 전송 → 409면 확인창 요청 신호), `rev` 비교(오래된 이벤트 무시), 회전 중 미룬 반영.
- **브라우저 2개 동시 시나리오** (`tests/e2e/2단계_시나리오.md`, Playwright로 브라우저 창 2개를 폰 화면 크기로 띄움, 진사 실행):
  1. A가 그룹 만들기 → 초대 링크를 B가 열고 닉네임 입력 → 서로 멤버 목록에 보임.
  2. A가 메뉴 추가·끄기 → B 화면에 3초 안에 반영.
  3. A가 돌리는 도중 B가 메뉴를 추가 → A의 회전은 그대로, 끝난 뒤 목록에 반영.
  4. A가 다시 돌리기 → B 화면에 "오늘 넘김" 태그.
  5. A가 확정 → B 상단 배지가 3초 안에 같은 메뉴, 결과 카드는 A에게만.
  6. B가 같은 메뉴판을 확정 시도 → "A님이 ○○로 확정했어요. 바꿀까요?"
  7. A를 오프라인으로 바꾸고 확정, 그사이 B가 다른 메뉴로 확정 → A 다시 연결 → A에게 덮어쓰기 확인창.
  8. 마지막에 두 창의 기록 화면과 `GET /history` 응답을 비교 → 완전히 같음.
- **실제 폰 2대 확인**은 HTTPS 서버가 있어야 자연스럽다. 공장은 위 흉내 시험까지 하고, 실제 폰 확인은 3단계 배포 직후 사장님 확인 항목으로 넘긴다(결정 필요 6번). 원하시면 공장 PC의 개발 서버를 같은 와이파이에서 폰으로 여는 방법도 안내한다(HTTPS가 아니라 설치 기능만 빼고 확인 가능).

## 4. 2단계 서버 API·WebSocket 초안

### 4.1 공통

- 주소 앞부분 `/api`. 요청·응답은 JSON. 인증은 `Authorization: Bearer <기기 토큰>`.
- 토큰: 서버가 무작위 32바이트(base64url)로 만들어 **한 번만** 돌려준다. DB에는 SHA-256 해시만 저장. 기기는 `hanjan.v1.device.token`에 보관(1단계 device 키에 추가).
- 그룹 데이터를 다루는 모든 API는 "토큰의 멤버가 그 그룹 소속인가"를 확인한다. 메뉴판·메뉴 API는 메뉴판 → 그룹을 거슬러 올라가 확인한다.
- 오류 모양: `{ "error": { "code": "...", "message": "화면에 그대로 보여 줄 한국어 문구" } }`

| 코드 | HTTP | 뜻 |
|---|---|---|
| `UNAUTHORIZED` | 401 | 토큰 없음·틀림·나간 멤버 |
| `FORBIDDEN` | 403 | 다른 그룹의 데이터 |
| `NOT_FOUND` | 404 | 없는 그룹·메뉴판·메뉴·초대 코드 |
| `VALIDATION` | 400 | 빈 값, 길이 초과 |
| `DUPLICATE_NAME` | 409 | 같은 이름 메뉴 |
| `ALREADY_CONFIRMED` | 409 | 오늘 이미 확정됨 (`existing: { name, nickname, confirmedAt }` 포함) |
| `LIMIT_REACHED` | 422 | 메뉴 16개·메뉴판 10개 초과 |
| `RATE_LIMITED` | 429 | 초대 코드 시도 초과 (`retryAfterSec` 포함) |

- 입력 길이(가안, 결정 필요 7번): 그룹 이름 1–20자, 닉네임 1–10자, 메뉴판 이름 1–12자, 결과 문구 1–20자, 메뉴 이름 1–20자(원본). 앞뒤 공백 제거 후 검사.
- 초대 코드: 6자리, 헷갈리는 글자(0·O·1·I·L)를 뺀 대문자+숫자 31종(결정 필요 3번). 초대 링크는 `https://hanjan.pygprg.com/?join=ABC234`.
- 시도 횟수 제한: 초대 코드 조회·참여는 IP당 10분에 10번(서버 메모리에 기록, 패키지 없이 구현). Nginx 뒤에 있으므로 `trust proxy`를 켜고 `X-Forwarded-For`를 쓴다.

### 4.3 WebSocket(Socket.IO) 이벤트 초안

- 접속: `io({ auth: { token, groupId } })`. 서버는 토큰·소속을 확인하고 `group:{gid}` 방에 넣는다. 실패하면 `connect_error`(메시지 `UNAUTHORIZED`/`FORBIDDEN`) → 기기는 토큰을 지우고 시작 화면으로.
- 접속·재접속이 되면 기기가 `GET /state`를 다시 부른다(놓친 이벤트 보충).
- Socket.IO 클라이언트 파일은 서버가 `/socket.io/socket.io.esm.min.js`로 직접 준다(외부 CDN 안 씀, 서비스 워커 캐시 대상).
- 모든 서버 → 기기 이벤트 공통 필드: `{ eventId, at, by: { memberId, nickname } }`.

| 이벤트 (서버 → 기기) | 내용 | 기기가 하는 일 | 단계 |
|---|---|---|---|
| `board:updated` | `{ board }` (items·오늘 넘김·오늘 확정·어제 메뉴·`rev`) | `rev`가 크면 갈아 끼움, 회전 중이면 그리기만 미룸 | 2 |
| `board:created` | `{ board }` | 탭 추가 | 2 |
| `board:deleted` | `{ boardId }` | 탭 제거, 보던 판이면 첫 판으로 + 알림 | 2 |
| `boards:reordered` | `{ boardIds }` | 탭 순서 | 2 |
| `history:confirmed` | `{ boardId, entry: { date, name, nickname, confirmedAt }, replaced: { name, nickname } \| null }` | 배지·태그 갱신, 남이 확정했으면 짧은 알림("○○님이 △△로 확정했어요") | 2 |
| `member:joined` / `member:left` | `{ member }` | 멤버 목록 갱신, 내가 `left`면 시작 화면 | 2 |
| `day:changed` | `{ today }` | 한국 자정. 오늘·어제·넘김 다시 계산, `GET /state` | 2 |
| `group:deleted` | `{ groupId }` | 토큰 지우고 시작 화면 | 4 |
| `history:changed` | `{ boardId, date, entry \| null }` | 기록·배지 갱신 | 4 |
| `spin:started` | `{ boardId, names, from, delta, durationMs, startedAt }` | 같은 회전 재생(결과 카드는 안 띄움) | 4 |

| 이벤트 (기기 → 서버) | 내용 | 단계 |
|---|---|---|
| (없음) | 2단계에서는 모든 쓰기를 REST로 한다 | 2 |
| `spin:start` | `{ boardId, names, from, delta, durationMs }` → 서버가 같은 방 다른 기기에 `spin:started`로 전달 | 4 |

## 5. 데이터 모델 (2단계 SQLite) — 기획서 표에 더한 것만 표시

| 테이블 | 열 | 제약·색인 | 기획서 대비 |
|---|---|---|---|
| groups | id, name, invite_code, owner_member_id, created_at | `invite_code` UNIQUE | 같음 |
| members | id, group_id, nickname, token_hash, joined_at, **left_at** | `token_hash` UNIQUE | `left_at` 추가(나간 멤버의 기록에 닉네임을 남기려고 행을 지우지 않음) |
| boards | id, group_id, name, result_lead, template, exclude_yesterday, sort_order, updated_at, **rev** | 그룹당 10개는 코드에서 검사 | `rev` 추가(이벤트 순서 판정) |
| items | id, board_id, name, is_on, sort_order | UNIQUE(board_id, name) | 같음 |
| skipped | board_id, date, name | PRIMARY KEY(board_id, date, name) | 같음 |
| history | board_id, date, name, member_id, confirmed_at | UNIQUE(board_id, date), INDEX(board_id, date DESC) | 같음 |

- id는 무작위 문자열(예: 12자 base64url). 숫자 순번을 쓰지 않아 다른 그룹 id를 짐작하기 어렵게.
- WAL 모드를 켠다(읽기와 쓰기가 서로 막지 않게, 백업도 안전).
- 서버와 브라우저가 `pool.js`·`kst.js`·`templates.js`를 함께 import 한다(`server/`가 `../client/js/...`를 불러옴). 제한값·템플릿·어제 메뉴 계산이 한 곳에만 있다.

## 6. 승인 요청 사항

### 6.1 이 설계 자체
사장님이 이 문서를 읽고 **"승인"**이라고 답해 주시면 0단계부터 시작한다. 단계가 끝날 때마다 결과를 보고한다.

### 6.2 따로 승인이 필요한 일
| 시점 | 내용 | 이유 |
|---|---|---|
| 2단계 시작 | npm 패키지 설치: `express`, `socket.io`, `better-sqlite3`, 시험용 `socket.io-client` | 팀 규칙상 지시 없는 패키지 설치 금지. `better-sqlite3`는 기계어로 빌드되는 패키지라 서버에서도 설치가 필요(7장). 대안: Node 22에 들어 있는 `node:sqlite`(아직 실험 기능 표시가 뜸)를 쓰면 이 패키지는 빼도 됨 |
| 3단계 | `git push`, 서버 배포 | 사장님이 직접 함 |

### 6.3 결정이 필요한 것 (가안을 적어 둠. 그대로 두셔도 됨)
1. **빈 메뉴판의 결과 문구 기본값**: 가안 "오늘의 선택은".
2. **오프라인일 때 메뉴 편집**: 가안 "막음"(돌리기·확정·다시 돌리기만 가능).
3. **초대 코드 글자**: 가안 "헷갈리는 글자를 뺀 대문자+숫자 6자리". 숫자 6자리만 원하시면 바꿈(그 경우 시도 횟수 제한이 더 중요해짐).
4. **1단계에서 만든 메뉴판·기록을 그룹 만들 때 옮기기**: 가안 "옮김"(그룹 참여하는 사람은 옮기지 않음).
5. **오프라인 확정을 받아 주는 기간**: 가안 "오늘·어제까지".
6. **"폰 2대" 시험**: 가안 "공장은 폰 화면 흉내 브라우저 2개로 시험, 실제 폰 2대 확인은 배포 직후 사장님".
7. **입력 길이**: 가안 그룹 이름 20자, 닉네임 10자, 메뉴판 이름 12자, 결과 문구 20자.
8. **담당 영역 맞춤**(1장 표): 팀 규칙의 `src/`를 이 앱의 `client/`·`server/`로 읽는 것.

## 7. 사장님이 직접 하실 일

### 0단계 (공장 작업과 동시에 해 두시면 됨) — hermes-server 준비
1. SSH로 hermes-server 접속 (Ubuntu 24.04).
2. 시스템 업데이트: `sudo apt update && sudo apt upgrade`.
3. Node.js 22 LTS 설치 (NodeSource 저장소 또는 nvm). 확인: `node -v`가 v22.x.
4. `better-sqlite3` 빌드 대비 도구: `sudo apt install build-essential python3`.
5. Nginx 설치: `sudo apt install nginx`, 브라우저로 `http://hanjan.pygprg.com` 기본 화면 확인.
6. Lightsail 콘솔 → 네트워킹 → 방화벽(IPv4·IPv6 모두): 80, 443 열기. 22(SSH)는 **그대로 둔다** — 내 IP로 제한하면 Lightsail 브라우저 SSH가 끊김(2026-11-05 인계 메모).
7. DNS 확인: `dig +short hanjan.pygprg.com` 이 `13.239.72.61`.
8. HTTPS 인증서: `sudo apt install certbot python3-certbot-nginx` → `sudo certbot --nginx -d hanjan.pygprg.com` → `https://` 접속 확인, `sudo certbot renew --dry-run` 확인.
9. PM2 설치: `sudo npm install -g pm2`.
10. 앱 자리 만들기: 예 `/srv/hanjan` (코드), `/srv/hanjan-data` (DB·백업, 앱 사용자만 쓰기).

### 2단계
11. 6.2의 패키지 설치 승인.
12. (원하시면) 같은 와이파이에서 폰으로 공장 개발 서버 열어 보기.

### 3단계 — 배포 (`deploy/배포안내.md`에 명령어까지 순서대로 적어 드림)
13. 공장 커밋을 저장소에 `git push` → 서버에서 `git clone`/`git pull` (또는 파일 복사).
14. 서버에서 `npm ci --omit=dev`.
15. `.env` 파일 직접 만들기(`.env.example` 참고: 포트, DB 경로). 공장은 비밀값을 만들거나 보지 않음.
16. `deploy/nginx.conf`를 `/etc/nginx/sites-available/`에 넣고 연결 → `sudo nginx -t` → `sudo systemctl reload nginx`.
17. `pm2 start deploy/ecosystem.config.js` → `pm2 save` → `pm2 startup`(나오는 명령 한 줄 실행) → 서버 재부팅 후 자동 실행 확인.
18. 백업: `crontab`에 `deploy/backup.sh` 하루 1회 등록, Lightsail 자동 스냅샷 켜기(유료 여부 확인).
19. 배포 후 확인: `https://hanjan.pygprg.com` 열림 / 아이폰(사파리 → 공유 → 홈 화면에 추가)·안드로이드(크롬 → 앱 설치) 설치 / 실제 폰 2대로 확정·넘김 반영 / 백업 파일 생성.
20. 멤버들에게 초대 링크 보내고 1주일 사용, 불편 사항 모으기.
