## 확정된 세부 규칙 (설계 3.2를 구체화한 것 — 여기와 다르게 하려면 먼저 보고)

### 저장 (`client/js/store-local.js`만 localStorage를 만진다)
- 접두어 `hanjan.v1.`, 키 `boards`, `history`, `skipped`, `device` (설계 3.2 표 그대로). 0단계의 `lunchRoulette.v1.*`는 읽지도 옮기지도 않는다.
- 모든 접근은 원본처럼 try/catch. 깨진 JSON·모양이 틀린 값(예: `skipped`가 null, `boards`가 배열 아님)은 기본값으로 대체.
- 처음 실행(`boards`가 없거나 빈 배열): "점심" 템플릿 메뉴판 1개 생성.
- **id는 `crypto.randomUUID()`로 만든다. `Math.random`을 쓰면 안 된다** — 0단계 비교 시험이 `Math.random` 시드로 원본과 당첨 결과를 맞춰 보기 때문.
- `history[boardId]`는 날짜 오름차순으로 유지, 제한 없이 보관. 하루 1건(같은 날짜면 덮어씀).
- 확정하면 그 메뉴판의 `skipped`만 `{date: today, names: []}`.
- `device`: `{ sound: false, lastBoardId: null, nickname: "" }`. 소리·마지막 메뉴판도 store를 통해서만 읽고 쓴다.

### 저장소 약속(인터페이스) — 모두 Promise 반환
```
getState() → { today, boards[], skipped: {[boardId]: names[]}(오늘 것만), history: {[boardId]: entries[]} }
getDevice() / setDevice(patch)
createBoard({ name, resultLead, template, excludeYesterday }) / updateBoard(id, patch) / deleteBoard(id) / reorderBoards(ids)
addItem(boardId, name, index?) / setItemOn(boardId, itemId, on) / removeItem(boardId, itemId) / resetBoard(boardId)
addSkip(boardId, name) / clearSkip(boardId)
confirm(boardId, name, { overwrite }) → { ok: true }   (1단계는 충돌이 없으므로 항상 ok)
listHistory(boardId, { before, days }) → { entries, hasMore }
stats(boardId, range)  // range: 30 | 90 | "all"
subscribe(listener)    // 다른 탭의 storage 이벤트
```
- 오류(16개 초과, 중복, 10판 초과 등)는 `{ ok:false, code, message }`로 돌려준다. message는 화면 문구 그대로: "16개까지 넣을 수 있어요.", "이미 있는 메뉴예요.", "메뉴판은 10개까지 만들 수 있어요.", "메뉴판은 1개 이상 있어야 해요."(마지막 1개 삭제 시).
- "삭제 후 되돌리기"는 `addItem(boardId, name, index)`로 원래 자리에 다시 넣는다(원본처럼). 같은 이름이 그사이 생겼으면 중복 오류 그대로.

### 날짜 `client/js/kst.js`
- `todayKST(now = new Date())` = `new Intl.DateTimeFormat("en-CA",{timeZone:"Asia/Seoul",year:"numeric",month:"2-digit",day:"2-digit"}).format(now)`.
- `addDays(dateStr, n)` (문자열 날짜 계산, UTC 기준으로 계산해 시간대 영향 없음).

### 템플릿 `client/js/templates.js`
| id | 기본 이름 | 결과 문구 | 메뉴 |
|---|---|---|---|
| `empty` | 새 메뉴판 | 오늘의 선택은 | 없음 |
| `lunch` | 점심 | 오늘 점심은 | 김치찌개, 제육볶음, 돈가스, 짜장면, 국밥, 비빔밥, 햄버거, 샐러드 |
| `drinks` | 술 한잔 | 오늘 먹으러 갈 곳은 | 고깃집, 치킨집, 횟집, 곱창집, 족발·보쌈, 전집, 이자카야, 호프집 |

상수: `MAX_ITEMS=16`, `MAX_ITEM_NAME=20`, `MAX_BOARDS=10`, `MAX_BOARD_NAME=12`, `MAX_RESULT_LEAD=20`.

### 기록·통계 순수 함수 `client/js/records.js` (2단계 서버도 씀)
- `sliceHistory(entries, today, { before, days=30 })`: `before`(없으면 today+1) 미만, `before-days` 이상인 날짜를 **최신순**으로, `hasMore` = 그보다 오래된 기록이 있는지.
- `countByName(entries, today, range)`: 30 = 오늘 포함 최근 30일(today-29 ~ today), 90 동일, "all" 전체. 결과 `[{name,count}]` 횟수 내림차순 → 같으면 `localeCompare("ko")` 순.

### 화면 동작
- 결과 카드 첫 줄 = 메뉴판 `resultLead`. 상단 배지 = `"오늘 " + 메뉴판 이름 + " 확정: " + 메뉴` (점심판이면 원본과 같은 문구).
- "처음 메뉴로 되돌리기" 확인창: 템플릿 메뉴가 n개면 `메뉴를 처음 {n}개로 되돌릴까요? 지금 목록은 사라져요.`, 빈 템플릿이면 `메뉴를 모두 비울까요? 지금 목록은 사라져요.`
- `excludeYesterday:false`인 메뉴판은 `computePool`·`itemTag` 모두에 `yesterday: null`을 넘긴다(진육 0단계 지적).
- 회전 중(`body.busy`)에는 탭 줄·"+"·"기록" 버튼도 조작 불가. 대화창(메뉴판 관리·기록)이 열려 있으면 스페이스바로 돌리지 않는다.
- 탭 관리 창 열기: "+"(새로 만들기), 탭 길게 누르기(0.5초) 또는 `contextmenu` 이벤트(우클릭·키보드 메뉴 키)로 그 메뉴판 편집.
- 메뉴판을 바꾸면 `device.lastBoardId` 저장, 새로고침하면 그 메뉴판이 열림(없어졌으면 첫 메뉴판).
- 다른 탭에서 바뀌면(subscribe) 다시 그린다. 회전 중이면 회전이 끝난 뒤.
- 기록 화면의 "확정한 사람": 1단계엔 닉네임이 없으므로 `device.nickname`이 비어 있으면 "나"로 표시(저장은 빈 문자열 그대로).
- `<title>`은 `한잔메뉴룰렛`.
