# Digital Memoir — UI 개선안 (Phase 2, Before → After)

- **작성일**: 2026-07-19 / **담당**: 진록(진사 영역 대행)
- **입력**: `docs/research/ui-audit-2026-07-19.md` (Phase 1 실측)
- **원칙**: 사진은 "분위기(무드)"로 후퇴시키고, **콘텐츠를 주인공으로**. 고령 사용자 포함(100세 앱) → 대비·타깃·가독성 우선. 기존 스택(Next.js+Tailwind, Pretendard/Lora, 블루-네이비 팔레트) 유지하며 저비용 고효과 순으로 제안.

## A. 디자인 토큰 재정의 (모든 개선의 기반)

### A-1. 컬러 — Before → After
**Before**: primary 블루 `#1C7FB8`, ink 네이비 `#0C2D48`, 크림 카드 `rgba(248,252,254,.6)` 2색 위주. 상태색·그레이스케일 부재.

**After (제안 토큰)**:
```
--ink            #0C2D48   /* 본문 텍스트 (유지) */
--ink-70         #48627A   /* 보조 텍스트 — 불투명 그레이로 고정(반투명 대신) */
--ink-50         #7A8C9C
--primary        #176699   /* 기존 #1C7FB8를 약간 어둡게 → 흰 배경 AA 4.5+ 확보 */
--primary-strong #0F4E78
--surface        #FFFFFF   /* 카드: 반투명(.6) → 불투명 흰색 (대비 확정) */
--surface-sub    #F1F5F8
--line           #E2E8F0
--success        #2E8B57
--warning        #C9781A
--danger         #C0392B
```
- ⚠️ **[Phase3 정정] 다크모드 토큰 필수**: 설정에 다크모드 토글이 실재하므로 위 토큰은 **라이트/다크 쌍으로 Sprint 1에 함께 정의**한다(라이트만 정의 시 다크 대비 재붕괴 → 재작업). B-1 오버레이 그라디언트도 하드코딩 금지, 토큰 경유.
- **핵심 변경**: 카드 배경을 **불투명 흰색**으로. 사진 위 반투명 카드가 대비 붕괴의 주범(P0-3)이므로, 카드는 사진을 가리고 그 안에서 대비를 확정한다. 사진은 카드 "바깥 여백"에서만 은은하게 보이게.
- 보조 텍스트를 `rgba(ink,.7)`(사진 위에서 대비 요동) → **불투명 그레이 토큰**으로 교체.

### A-2. 타이포그래피 — Before → After
**Before**: `<p>`가 Lora 세리프·**bold 700**·18px·**primary 블루** (본문 문단이 파랗고 굵음 → 위계 혼란). 크기 4종(12/16/18/30)만 사용.

**After (타입 스케일)**:
| 역할 | Before | After |
|---|---|---|
| 페이지 h1 | (홈은 없음) | Lora/Pretendard **28–32px, 700, ink** |
| 섹션 h2 | 30px 산발 | 20–22px, 700, ink |
| 본문 p | Lora **700 blue 18px** | **Pretendard 400, 16px, ink, line-height 1.7** |
| 보조/캡션 | 12px | 13–14px, ink-50 |
| 세리프(Lora) | 본문에 오용 | **감성 인용/회고 문장에만** 한정 사용 |
- 본문은 **Pretendard 레귤러 네이비**로. Lora는 회고/명언 등 "감성 강조" 블록에만.

### A-3. 스페이싱/레이아웃 그리드
- 콘텐츠 최대폭 **`max-w-3xl`(768px)** 중앙 정렬 기본, 대시보드/목록은 **`max-w-5xl`+반응형 그리드**. (P1-1 좌측 쏠림 해소)
- 카드 radius `rounded-2xl`, 그림자 `shadow-sm`(사진 위 부양감), 패딩 `p-6 md:p-8`.

## B. 배경 사진 처리 — 최우선 (P0-1)

이 항목 하나가 인상의 80%. 3개 옵션을 제시하되 **B-1 권장**.

### B-1. (권장) "무드 히어로 + 콘텐츠 서피스" 분리
**Before**: `beach.jpg`가 `fixed / opacity:1 / filter:none`로 전 화면·전 페이지를 100% 덮음. 콘텐츠는 반투명 카드로 사진 위에 떠 있고 하단 절반은 사진만.

**After**:
- 사진은 **상단 히어로 영역(높이 220–280px)** 또는 **콘텐츠 뒤 고정 배경이되 강한 오버레이**로 후퇴.
- 배경 유지 시:
  ```css
  .app-bg{ opacity:1; filter:saturate(.9); }
  .app-bg::after{ content:""; position:absolute; inset:0;
    background:linear-gradient(180deg, rgba(248,252,254,.86), rgba(248,252,254,.96)); }
  ```
  → 사진을 **10~14% 정도만 비치는 은은한 무드**로. 콘텐츠 영역은 밝은 서피스가 덮어 대비 확정.
- 본문 콘텐츠 컨테이너는 `bg-surface`(불투명)로 감싸 사진과 분리.
- **효과**: "죽은 하단 절반" 소멸, 대비 문제 동시 해결, 감성(사진) 유지.

### B-2. (대안) 페이지별 은은한 배경 제거, 홈에만 히어로 사진
내부 페이지는 순수 `--surface-sub` 배경, **홈 상단에만** 사진 히어로. 가장 "앱다운" 정돈감. 감성은 약해짐.

### B-3. (대안) 사진 유지하되 좌우 여백(gutter)에만 노출
콘텐츠 카드가 화면 중앙 서피스를 차지하고, 사진은 카드 양옆에만. 와이드에서 멋있지만 모바일 효과 적음.

## C. 홈 재설계 — 대시보드화 (P0-2)

**Before**: `<main>` 텍스트 0자. 사진 위 흐린 "내 인생의 기록 / 먼저 설정에서…" + 텍스트링크 CTA만.

**After — 온보딩 상태 / 데이터 있는 상태 2단 설계**:

```
┌───────────────────────────────────────────────┐
│  [히어로/무드 배경 · 상단 240px]                 │
│  안녕하세요, {이름}님 👋   ("이름 설정하기" 온보딩) │
│  "오늘도 당신의 이야기를 기록해요"                │
├───────────────────────────────────────────────┤
│  [진행 카드]  기록한 날 12 · 남은 인생 XX,XXX일   │ ← 설정의 생년월일/기대수명 활용
│  [빠른 작성]  ✍️새 독백  ✉️편지쓰기  📷추억추가    │ ← primary 버튼 3개
├───────────────────────────────────────────────┤
│  최근 기록                              [전체보기]│
│  ▸ 독백  "..."           2일 전                  │
│  ▸ 추억  "제주 여행"      1주 전                  │
├───────────────────────────────────────────────┤
│  섹션 바로가기 (2×5 카드 그리드)                 │
│  [독백][편지][자산][관계][추억]                  │
│  [타임캡슐][타임라인][버킷리스트][설정]           │
└───────────────────────────────────────────────┘
```
- **온보딩 미완료 시**: 흐린 문구 대신 **불투명 카드**에 큰 제목 + **`저장` primary 버튼("이름·생년월일 입력하기")** 배치(텍스트링크 → 버튼 승격, P0-2/접근성).
- 홈에 **`<h1>` 추가**(현재 0개, P1-2).
- 빈 상태여도 "섹션 바로가기 카드"로 화면이 채워져 "빈 페이지" 인상 제거.

## D. 컴포넌트 개선

### D-1. 카드(Empty State 포함)
**Before**: 반투명 카드, 사진 비침. **After**: 불투명 `bg-surface` + `border border-line` + `shadow-sm`. 내부 대비 확정.

### D-2. 버튼
- **Primary**: `bg-primary text-white h-11(44px) px-5 rounded-xl` — 높이 44px로 타깃 확보(P1-3). hover `bg-primary-strong`.
- **Secondary**: `border border-line bg-white text-ink`.
- 현재 문장 속 텍스트링크 CTA → **버튼 컴포넌트로 통일**.

### D-3. 사이드바(데스크톱)
**Before**: 링크 높이 34px(타깃 미달). **After**: 항목 높이 **44px**(`py-2.5`), 활성상태 유지, `aria-current="page"` 추가. 로고 하위 "Digital Memoir" 12px → 13px ink-50.

### D-4. 모바일 하단 탭바 (P1-4)
**Before**: 사진 위에 얹혀 대비 약함, 5개만 노출.
**After**:
- **불투명 서피스 바** `bg-white/95 backdrop-blur border-t border-line` — 사진과 분리.
- 아이콘 24px + 라벨 11→12px, 탭 높이 **56px**, 터치영역 44px+.
- 5번째 탭 "메뉴"는 **바텀시트**로 나머지 5개 섹션(편지·관계·타임캡슐·타임라인·버킷리스트) 노출 + 라벨.

### D-5. 폼(설정/온보딩)
- 라벨-인풋 연결(`<label for>`), 인풋 높이 44px, `생년월일`은 네이티브 date + 안내문. 저장 성공 시 토스트(success 토큰).

## E. 접근성·시맨틱 (P0-3, P1-2, P1-3)
- 모든 페이지 **`<h1>` 보장**, 헤딩 순서 정상화.
- 랜드마크에 `aria-label`: `<nav aria-label="주요 메뉴">`, 모바일 `<nav aria-label="하단 탐색">`, `<main>` 유지.
- 텍스트 대비 **AA 4.5:1**(큰 텍스트 3:1) 충족 — 카드 불투명화 + primary `#176699` 조정으로 달성.
- 인터랙티브 타깃 **최소 44×44px**.
- 포커스 링 `focus-visible:ring-2 ring-primary` 전역 추가(키보드 내비게이션).

## F. 성능·브랜딩 (P0-4, P1-5, P2-1)
- **beach.jpg**: ⚠️ **[Phase3 정정]** 현재 CSS `background-image:url()`로 로드됨 → `next/image` **적용 불가**. 경량화는 두 방식 중 택1: (a) **WebP/AVIF 재인코딩 후 CSS `url()` 교체**(구조 변경 최소, 권장) 또는 (b) 배경을 전용 `<img>`/컴포넌트로 구조 변경 후 `next/image`. **WebP/AVIF + 반응형** 적용, 442KB → 목표 **<120KB**(모바일 <60KB). 배경이므로 흐림 처리로 저해상도 허용. **Sprint 1에선 배경 구조 미변경(오버레이만), 경량화는 Sprint 3.**
- **파비콘 세트 추가**: `favicon.svg`, `favicon.ico`, `apple-touch-icon.png`, `icon-192/512.png` + `manifest.json`(PWA 여지). 콘솔 404 제거.
- 클라이언트 렌더 빈 화면(P2-1): 주요 목록에 **스켈레톤 UI** 도입해 "빈 페이지 깜빡임" 완화.
