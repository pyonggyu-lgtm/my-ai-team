## 반드시 반영할 항목 (Phase 2 문서에 errata로 적용 완료)
1. **[정확성] beach.jpg는 CSS `background-image`다 → `next/image` 적용 불가.**
   - `next/image`는 `<img>`/컴포넌트에만 동작. 배경 경량화는 (a) WebP/AVIF 재인코딩 후 CSS `url()` 교체 또는 (b) 배경을 전용 `<img>`/컴포넌트로 구조 변경, 둘 중 하나를 먼저 결정해야 함.
   - 조치: Sprint 1에서는 배경 **구조 미변경**, CSS 오버레이(B-1)만 적용. 이미지 경량화는 Sprint 3.
2. **[누락] 다크모드 토큰을 Sprint 1에 함께 정의.**
   - 설정에 다크모드 토글 실재. A-1 토큰/B-1 오버레이 그라디언트가 라이트 전용 하드코딩이면 다크에서 대비 재붕괴 → 재작업.
   - 조치: 토큰을 **라이트/다크 쌍**으로 정의, 오버레이도 토큰 경유.

## 검증 정정 (리뷰어 지적 중 실측과 불일치한 부분)
- 리뷰어는 "모바일 하단탭은 44px 미달로 잡히지 않았다(모바일 소형 타깃 1개)"고 했으나, **`audit.json` 모바일 실측은 `smallCount:5`** (홈·독백·자산·추억 탭 + 메뉴 버튼 모두 **38px 높이**). 따라서 **P1-3/P1-4의 모바일 타깃 근거는 유효**, 하향하지 않음.
- 사이드바 링크 높이는 리뷰어 "36px"가 아니라 **실측 34px**(`audit.json` desktop `h:34`). 결론(모두 <44) 동일. 조사 문서 수치 유지.
- 즉, D-4 바텀시트는 "정보 접근성(10개 중 5개만 노출)" + "38px 타깃" **양쪽 근거 모두** 유효.

## 수용한 우선순위 조정
- **홈 대시보드(C) 분할**: Sprint 1에는 "온보딩 카드 + `<h1>` + 섹션 바로가기 그리드"만. **진행률/최근기록 피드는 Sprint 2**(10개 섹션 로컬 데이터 교차 집계 = 숨은 M~L 공수).
- **F 과잉 분리**: 파비콘 404 해소는 Sprint 1 유지, `manifest.json`/PWA는 후순위로 분리.
- **상태색(success/warning/danger)**: Sprint 1엔 토큰만, 적용은 Sprint 3(현재 상태표현 UI 거의 없음).

## 배경 처리 최종 권고: **B-1** (오버레이 + 불투명 서피스)
- B-2는 앱 정체성(회고/자서전)의 감성 자산을 버림. B-3(거터 노출)은 **모바일 전면 지배 문제를 못 품**(모바일 거터 없음). B-1은 CSS만으로 P0-1·P0-3 동시 해결, 데스크톱/모바일 공통 커버, 롤백 용이. 단 오버레이 값은 다크 대응 토큰으로.

## 진오(구현자) 주의사항 3
1. **beach.jpg = CSS 배경.** Sprint 1은 구조 손대지 말고 오버레이만. 경량화는 방식 결정 후 S3.
2. **토큰은 라이트/다크 쌍으로 한 번에.** 오버레이 그라디언트도 하드코딩 금지.
3. **전역 `p{}`가 Lora/700/blue.** Pretendard로 되돌리면 의도적 Lora(회고/인용)까지 바뀜 → 인용 클래스 분리 후 시각 위계 회귀 확인. 대비 실측 샘플이 4개로 협소했으니 primary #176699 반영 후 주요 텍스트/버튼/링크를 직접 재측정해 AA 확정.
